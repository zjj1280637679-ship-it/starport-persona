# 明清人物镜：甲申异闻录 · Story Pack v0.1

> 定位：原创架空历史奇幻叙事游戏。借鉴《苏丹的游戏》的“卡牌驱动、期限压力、资源调度、多线结局”的设计原则，不复制游戏资源、文本、卡牌分类及机制细节。
> 史料与神异须严格区分；虚构奇物和角色不冒充历史史实。本作涉及多地区、多社群、多政治联盟，历史阵营共鸣不代表现实血统或能力。

## 1. 故事体验

开局公元1644，玩家是京师陷落前夕被派往废弃档馆的一名小吏（可换身份模板）。
首个超自然事件：一封来自未来的密诏由已故信使送达，信中写出玩家尚未发生的选择。
以“甲申十四夜”为第一套可完整通关故事包。不是28道测试题，也不是无限聊天室。

**可玩的自由**：除了3个可见建议行动外，游客可自由向主持人提出计划、交涉、调查、偷换、伪装、毁约、组合物品等。行动结算必须经规则校验；AI 既能应对文本自由度又不得暗改账本。
**惊奇的来源**：隐藏信息揭露、奇物新用途、NPC的真实动机、代价反噬、关系逆转、迟来的因果回收；不要靠随机放大事件或频繁添加奇物制造廉价惊吓。
**惊奇必须改变玩家后续能做的事情**。

## 2. 三层系统

A. **确定性游戏内核**：本机起步，未来可转后端。拥有当前天数、体力/钱粮/疑罪、关系、卡牌、事件状态、历史选择日志、成就。在每次行动后实施硬条件检测、资源扣除、移动和成就结算。只有内核拥有改写游戏状态的权力。

B. **AI 导演 / 酒馆主持人**：部署在既有 Cloudflare Worker + DeepSeek V4.1 Flash 上。使用一个 AI 服务分三种结构化任务模式（主持事件、理解自由行动、结局史官），避免三个独立代理同步增费。主持人可以写NPC对话、给候选行动、提议剧情演绎和卡牌联动；不得生成未注册的物品ID或可执行状态修改。自由操作经 JSON 白名单验证和内核 adjudicate；失败给原因和可选修正而不是假装成功。

C. **作者可控故事包**：定义时代背景、场景图、人物卡、事件库、物品卡、成就条件、伏笔及回收、结局和人物评价参考库。每个包可追加，不改内核。

## 3. 回合与章节

每个玩家动作处理为一个**叙事回合**，默认非随意扣天数。
- 谈话、观察、询问：不扣日，可以设有限次数与节奏防刷；仍可消耗模型 Token（需要限流）。
- 远行、交易、潜入、祭仪、布署：由规则内核判定扣除一天或资源。
- 每夜午夜处理期限、谣言传播、NPC关系、伏笔发芽。
- 第一故事包以第14夜或关键状态触发结局，不固定所有游客必须走完14天；允许提前终局或意外失败。
- **章节伏笔-偿付**：每个关键章节必须具备“钩子（目标）→阻碍→第一次逆转→代价→新机会”；至多保留少量未解悬念，后段优先回收前段伏笔。

### 第一篇章《死者的诏书》

1. 死者叩门：信中预告尚未做出的决定；可以读、藏、焚、求证，哪条路都引向下一层秘密。
2. 镇尸纸人：与受契约束缚的“纸人侍者”结缘，得到穿越封锁/递送消息的有限能力；代价是它不能背离旧誓约。
3. 红砂还魂：遇到一剂可暂借逝者七夜的丹药；归来者保留自己的动机，复活不意味着受玩家奴役。
4. 逆史星图：发现每次以预测改变选择，就会在地图上制造一个新的灾厄空白区。
5. 同盟与背叛：势力间的权宜联盟，奇物、忠诚与现实救援相撞；历史态度从具体行为显露。
6. 谁写下未来：玩家发现密诏的“笔迹”竟与自己某个可能的未来重合，进入深层选择。
7. 终局：保全生命/保全真相/占有奇物/逃往世外等多种结局。史官读卷，根据真实选择叙述最近的历史人物镜像，不能乱编史实。

## 4. 卡牌系统

每张卡至少包含 `id,type,rarity,title,artSlot,tags,description,charges,conditions,effects,restrictions,discoverable`。
卡牌是故事互动资源，不是单纯装饰。
- **奇物卡**：还魂丹、逆史星图等，有有限次数、代价和使用条件。
- **门客卡**：纸人侍者、边镇斥候、流亡书生等，有忠诚和秘密，每人仅有可解释的能力。
- **情报卡**：未来密诏、税粮暗账等，改变行动可用选项和NPC态度。
- **盟约卡**：跨势力交换承诺，短期帮助有违约成本。
- **因果/诅咒卡**：积欠的代价和风险，会延迟回访，不能随意从手牌删除。
- **命数卡**：关键事件倒计时与不可逆条件（不是复刻苏丹卡的四种类型）。

卡牌可有普通/珍稀/异宝/禁忌四级，但稀有度不必直接决定战力。一张普通的旧钥匙可以在隐藏场景中救命。

## 5. 成就收集

成就是局外收藏，默认保存本机（localStorage）；需要区分本局达成与历史解锁。所有成就必须由引擎事件触发，有证据句柄（`eventId,turn,flag`），不得根据模型一句“你获得了成就”直接授予。
- 发现类：亲见神异 / 完成秘卷的第一条印证
- 奇物类：借死人之口 / 星图第一次逆转
- 策略类：不耗奇物化解危机 / 同时维持两个互斥盟约（罕见）
- 伦理类：为陌生人舍弃异宝 / 保全证词而放弃权力
- 结局类：活过第十四夜 / 以书换命 / 世外桃源
- 隐藏类：识破传诏人的旧契约 / 诏书上的笔迹

达成条件由内核验证，成就可重复游玩永久解锁；AI 只描述发现时的动画与颁词。

## 6. 结局人物拟合

结局不是先计算16轴再匹配的强制试卷，而是读取**整场故事可追溯决策**：
- 人格偏好：应对新人与组织、人情与规则、计划与变局的实际方式。
- 政治光谱：中央/地方、改革/守旧、礼法/实用、权威/自治等不同剧情选择。
- 历史阵营共鸣：仅基于具体历史政治文化立场，绝不自动从姓名/族裔/宗教推断。
- 智谋：具体可核验的策略效果，失败也能产生精彩结局；不等于玩家现实 IQ。
- 输出最近镜像与2-3备选，解释相合与不同。数据不足时明确说“本次故事更接近文学化比照”，而不是伪装出高置信度百分比。

**整场卷宗读取**：保留原始 transcript 与每次可验证的 state diff；单次模型上下文放得下则读全量，否则按章节摘要+决策证据引用组合，不能声称在上下文上限之外直接读到完整历史。

## 7. AI结构化契约和安全边界

由 Cloudflare Worker 增加新版本接口（旧 `/api/analyze`、`/api/rewrite` 和 `/api/commentary` 暂保持不变），例如：
`POST /api/story/turn`
输入：故事包ID、当前 canonical state 摘要、可用 action id 列表、经过长度限制的最新对话及玩家输入、一次性 Turnstile token。
输出：`{narration,npcId,sceneId,proposedActionId,confidence,reasoningEvidence,artSlot}`。只接受已注册的事件/卡牌/行动/场景ID。
AI **只能提议**行动；内核 validate→apply→log 之后，才能改变卡牌数、忠诚、钱粮、结局和成就。
`POST /api/story/ending` 输入有证据的卷宗、结局状态、预定义角色池；输出文学化叙事+候选解释，禁止直接修改结果池。

严格长度上限、Turnstile、速率限制、单局对话预算和断路开关；服务器端持有 DeepSeek API Key，浏览器绝不接收。隐私明确披露“开启AI会发送本局对话”，默认本机存储；游客有权选择只走本地预写剧情演示。

## 8. 美术槽

沿用已有 `media.js` 的 graphic→image→GIF 契约，扩展：
- `story.jiashen.background`: 故事主背景（16:9）
- `scene.archive-night`: 夜雨档馆场景（16:9）
- `scene.ritual`: 回魂仪式场景（16:9）
- `npc.paper-servant`: 纸人侍者立绘（3:4）
- `npc.innkeeper`: 酒馆掌柜立绘（3:4）
- `card.revival-pellet`: 还魂丹物品卡图（3:4）
- `card.future-edict`: 未来诏书（3:4）
- `card.star-map`: 逆史星图（3:4）
- `achievement.first-revelation`: 首次窥见异闻徽章（1:1）
- `ending.ink-history`: 最终封面（9:16 或 4:5）

建议卡牌UI始终保留真实卡片框，不能只显示一段文字及数值。GIF 只给极少数“奇物觉醒”“隐藏成就”瞬间，尊重减少动态效果的浏览器设置。

## 9. 产品里程碑

**M0：故事核心验证**（独立子路径，不覆盖现有考试版）：1个故事包，7个事件、至少12张卡、8个成就、3种结局；本地确定性状态机，手机端对话+卡牌+成就UI。可完整通关。
**M1：AI导演联网**：Cloudflare新路由，DeepSeek对行动自由文本提供建议与合理回复，结构化权限限制；故障可离线通关。
**M2：史官镜像**：结局按完整证据日志产生四维低精度解释和历史人物最近邻。
**M3：高级叙事飞轮**：多NPC、记忆摘录、跨周目收藏、艺术资源升级、开放多故事包。

每个M阶段必须覆盖烟雾测试：非授权卡牌不能发放，负资源不能出现，成就只能按规则授予，当前会话不能读到别人的答卷，故事前后因果一致。

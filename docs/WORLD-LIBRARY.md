# 世界丛书与身份协议（探索性草案）

这是给 GM Agent 与后续开发者的**知识组织建议**，不是九格或二十七格的固定游戏规则。核心目标是：**只有在需要时阅读合适的知识，允许玩家以多重身份自由跨地区、跨社会阶层，同时保持已发生的因果。**

## 一、最小 GM 可只用一句话启动

> 你是开放式文字推理与冒险游戏的 GM / DM。根据世界事实、角色认知及玩家行动创造并推进故事；需要外部知识时查书，重要变化要留下可追溯记录。

这是“足够启动思考”的假设，不保证一条提示就自动拥有工具权限、持久记忆、多人隔离与有效裁判能力。那些是 Harness 的运行时职责。

## 二、书架的索引：地区 × **当地可接触的社会阶层**

| | 低层示例 | 中层示例 | 高层示例 |
| --- | --- | --- | --- |
| 京师 | 鬼市、难民、行会 | 衙署、幕僚、商会 | 宫廷、密诏、权臣 |
| 江南 | 运河、码头、草市 | 士绅、商帮、税务 | 军政、藩镇、秘密盟约 |
| 辽东 | 边民、流亡者、猎户 | 军镇、边市、使团 | 总兵议事、军事外交、政权中枢 |

这些名称是**演示性的目录条目**，不是必须建齐的文件，也不是严格难度曲线。地图之间可以跨行、跨列跳转；有关系、凭证或伪装便能越阶，而知名人物进入陌生地区也可能从低层重新开始。

“高阶地图”指能接触高权力的社会关系与事件，不代表角色战斗力、智商或主观强度高。

## 三、每卷薄 Skill 建议只回答五个问题

1. 这个地区/阶层的**现实条件与神异边界**是什么？
2. 谁掌握可被交换或争夺的资源、身份和权力？
3. 哪些矛盾、欲望或危险会自然产生故事？
4. 给 GM 2–3 个**非必经的启发例子**，让其即兴发挥。
5. 有哪些需要时才查阅的附录/插画索引？

例子（不是实际通关剧情）：

```markdown
# 辽东 / 中层 · 临时设定
边市与军镇并存，军粮与贸易路线决定小人物的命运。
总兵、幕僚、商旅、方士相互利用，谣言胜过证据的速度。
例子：伪使者被熟人识破；失踪军粮进入神秘交易；未死的将领借他人身份行走。
触发关键词：军粮、边市、使者、密约、纸人。
可检索的附录：npc/lord_*, relic/border_*, art/liaodong_*。
以上例子不必发生；玩家自由提出替代行动，GM 需要跟随。
```

书卷不必须是 Markdown 文件。可以是目录、可检索记录、嵌入向量索引；格式应由真实访问与维护需要决定。

## 四、身份不是一个静态等级

每位游客在每个地区都有可分离状态：

- **实际身份**：真实来历、现有能力、实际财产、真实政治关系。
- **表面身份/面具**：本人主动向外界展示的称谓、官职、通行证、冒名顶替。
- **本地被认可的通行层级**：能够接触到多少权力资源，跟真实能力不同。
- **关系**：敌对 / 中立 / 友善是粗略索引；具体 NPC 可各自有不同态度。
- **熟悉度**：新人、熟人、故人；影响初始信任而不是自动善恶。
- **授权/靠山与其失效条件**：拥有后台或作为傀儡可能直通高层；靠山倒台后可失效。
- **暴露与怀疑**：不同人可能知道不同的秘密，甚至相信相互矛盾的身份。

示例状态，不是永久 schema：

```json
{
  "currentRegion": "liaodong",
  "actualIdentity": "京师流亡书吏",
  "presentedIdentity": "权臣密使",
  "localAccessTier": "high",
  "localRelation": "neutral",
  "familiarity": "newcomer",
  "patron": "某权臣",
  "credential": "待核验的密令",
  "identityKnowledge": {
    "gateCaptain": "believes_envoy",
    "storekeeper": "suspects_false_id"
  }
}
```

**NPC 称谓是知识与动机的结果**：守门军士叫“钦使大人”，账房私下称“冒名之徒”，老友仍称乳名。改变“全局声望”不能自动覆盖每个人的认知。未经揭露的玩家真实身份不能像公告一样广播给所有 NPC。

## 五、书卷与动态卷宗是不同的东西

| 信息种类 | 来源 | 加载方式 | 能否直接当成已发生事实 |
| --- | --- | --- | --- |
| 总纲/目录 | 世界作者或共同创作 | 默认可用的简短索引 | 只有标记为既定设定的部分 |
| 地图分卷 | 当前地区 × 可接触阶层 | 当前情境按需加载 | 不行，例子是灵感 |
| 附录 | NPC秘密、奇物、史料、素材 | 由 Agent 搜索并局部读取 | 需确认真实性与可见权限 |
| 会话卷宗 | 真实发生的交互和已确认事件 | 近期摘要+必要原始证据 | 是；变更应记录来源 |
| 世界变更日志 | 工具的提交结果 | 增量读取和重建 | 是；可回滚/审计 |

隐藏秘密要有“GM 可知但玩家尚未知”的可见性标记；GM 查阅不是游戏内 NPC 突然全部知晓。

## 六、从书到游戏的一次典型流转

访客在京师以逃亡书吏身份收到密诏 → GM 查京师低阶分卷 → 玩家决定伪装辽东使者 → GM 查询身份工具与所持凭证 → 在江南借商帮关系进入中层卷 → 某 NPC 认出真身，另一个仍以为他是使者 → GM 调度地图/关系附录，创造代价或意外 → Harness **只提交经过明确授权和校验的状态变化** → 下一次载入仍保留旧誓、旧仇、奇物与真实身份。

“可以抵达”不同于“必须成功”。拦截、拒绝、损失、伪装被识破也可以产生优质剧情，前提是因果可信。

## 七、最小工具语义（接口形式待定）

- **查书**：按地区、阶层、主题检索目录/段落，不一定要把全书塞进 prompt。
- **查档**：查询玩家状态、局部 NPC 认知、已发生事件及证据。
- **提出并提交变更**：GM 能建议人物/事件/卡牌/成就生成；Harness 做基本一致性与权限验证，提交后可追溯。
- **渲染**：返回文本、卡片、表格、按钮或素材 ID；浏览器按需拉取，禁止模型注入可执行 HTML/JS。
- **导出/迁移**：可重建故事和世界，兼容换模型、换框架、换世界。

以上只是目标能力，方法和工具名均可改。**不要因为想做漂亮的插件契约而把可用的简单文字 GM 原型推迟到很久以后。**

## 八、待验证的问题

- 一条极简 GM 提示词在不同模型上的自由行动表现、长期一致性与创造性各如何？
- 转换地区与身份时，是 Agent 主动翻卷更好，还是 Harness 先给轻量目录更好？
- 如何把 NPC 局部认知和世界真实事实同时保存、索引且防止泄密？
- 已有事件/资产怎样按需检索，才不会让成本和响应时间失控？
- 在临时发明物品/规则/成就时，什么程度的验证能保护一致性而不锁死想象？

请优先以真实玩家行动与可重放世界快照检验，而不是预设“应有多少书、多少卡、多少 token”。

# 目标、发现与开放问题 | Project Intent

版本：2026-10-16。性质：对需求与经验规律的工作性描述，随新证据更新，**不是固定设计规范**。

## 1. 核心目标（目的，而不是实现）

使普通游客无需自带模型 API，在一个网页中与 **AI GM / DM** 自由玩文字推理与叙事游戏。世界可由 Agent 即兴创造和逐回合更新；人物、秘密、物品、地位、局势和玩家选择能够跨回合保持连续；网页 Harness 负责可靠传递、保存、检索与表现。创作自由服务于值得经历的故事，而非让游客受限于人工预设选择题。

《明清人物镜》的明清历史奇幻、卡牌、历史人物拟合是**首个用来验证通用引擎的故事主题**，不是通用引擎的边界。未来可能承载宫廷权谋、异史、酒馆冒险、侦探、科幻、政治模拟等不同游戏。玩家可自选故事，亦可让 GM 临时创作。

## 2. 从现有实验发现的规律（区分观察与推断）

| 观察/问题 | 工作性推断（待证伪） | 对架构的启示 |
| --- | --- | --- |
| 固定 12/28 道历史题可以评分，却不像冒险 | 测量维度不能自动创造人物欲望、奇遇、风险与戏剧弧线 | 人物拟合宜作为游戏结局的可选解读，而非全程强制题型 |
| 预置七幕能演示卡牌、成就与终局，却无法处理玩家任意新策略 | 预编分支随可能行动组合快速膨胀 | 可由 GM 即时提议世界变化，再由 Harness 持久化和验证 |
| 角色/奇物若只存在当前回复中，后续容易遗忘或矛盾 | 模型单轮文本不天然等于可验证的世界状态 | 分离“已确立事实”“未证实传闻”“自由创造素材”；可追溯变化 |
| 整库插画并不需要同时出现在浏览器和模型输入中 | 资源索引和实际二进制文件可以按需传输 | 文本/表格/卡片为基础体验；插画是可选的按需资源层 |
| 同一个人在京师是官员，去辽东可能变外乡人或敌方密探 | 社会可达性属于“当地被认可的身份”，而不是全球等级 | 地区 × 可接触阶层选书，关系/熟悉度/伪装作为运行时修饰 |
| 高位可以靠权臣授权、冒名、傀儡替身获得，失去靠山又跌落 | 社会权力和实际能力、名义称谓不是同一属性 | 支持社会跃迁、身份面具、暴露风险、NPC各自信念 |
| 薄地图设定 + 少数示例仍能启发 AI 生成丰富情境 | 故事可从“约束条件与冲突种子”生成，而不需遍历完整剧情树 | 总纲常驻、分卷与附录按需读取；例子不当必经任务 |

以上是**发现/假说**，不是宣称已通过大规模用户测试的科学规律。使用反例与新数据推翻它们，正是未来 Agent 的职责。

## 3. 当前最小概念模型

```text
访客消息/界面操作
        ↓
通用网页 Harness ←→ 世界状态/玩家卷宗/会话存储
        ↓
    通用 AI GM
        ├─ 默认最薄提示：你是文字推理冒险的 GM / DM
        ├─ 世界总纲及目录：知晓有哪些书，何时查阅
        ├─ 当前分卷：地区 × 当地可接触阶层
        ├─ 附录：NPC、神异、史料、素材，按需检索
        └─ 工具：读取、提议/提交变动、素材引用、通用 UI
```

“Pi 式 Agent”指**精简运行时 + 提示词 + 可发现的技能/工具**。不隐含必须选用 pi SDK，也不隐含固定提示词、固定实现语言或自动具备无限上下文。

## 4. 世界丛书不是关卡清单

以 **地区 × 社会层级** 索引薄书卷，如京师/江南/辽东与低/中/高。每卷可短到一段背景、一份权力结构、几条矛盾与示例，不预设必经剧情。敌对/中立/友善、熟人/新人、真实身份/伪装身份、当地认知和大人物授权是**独立动态变量**；它们塑造 NPC 称呼与态度，不要求预写出 3×3×3 套完整剧本。

游客可以在任何地图上以高阶傀儡身份进入权力中心，也可在陌生地区失去原有地位，或通过隐藏身份参与敌对世界。跨地图流动是故事的发动机，不是异常情况。

具体技术语义参见 [WORLD-LIBRARY.md](WORLD-LIBRARY.md)。

## 5. 体验方向与观察维度（非 KPI、非硬上限）

- **自由**：玩家自己发明的策略能得到有因果、有代价的回应，而不只是被强行映射到三个按钮。
- **连续**：已确定的人、物、关系、恩怨与秘密跨地域、跨阶层仍被记得。
- **惊奇**：神奇仆人、复生宝药、伪装逆袭等意外，使玩家下一步的可能性发生真实变化，而非只靠夸张文案。
- **社会视角**：NPC 的称呼、服从、敌意取决于当地知识、真实/表面身份、权力关系，而非玩家永久数字等级。
- **轻量扩展**：添加一个地区/世界主要写薄设定与附录，不必改写核心程序。
- **表现**：纯文本与结构化表格可完整游玩；按需插画/GIF 增进沉浸，但不成为模型或游客的强制负担。
- **可持续**：秘密不泄漏、付费调用受控、多游客不互相串档、数据保存与权限边界可解释。

任何数量、示例事件、故事长度、资源规格都只是帮助观察的候选指标；未来 Agent 不应因文档写了“九卷”“十四夜”“十二张卡”而拒绝更好的方案。

## 6. 不由主观选择取消的现实条件

- GitHub Pages 静态网页无法秘密存放 API Key；若公众共用模型额度，需要安全的服务端代理、用量与滥用控制。
- 浏览器来源/CORS 本身不等于身份认证或预算保护；当前 Turnstile/限流只是部分防护。
- 完整会话可以存于磁盘/数据库，却不意味着一次模型调用能读无限 Token；检索和归纳需要留有来源。
- AI 对世界的提议与世界已经提交的事实，应有明确边界、验证与可追溯更新，防止虚构发卡或任意篡改。
- 玩家数据及群体属性不能被包装为科学测量或真实民族血统判断；历史奇幻与史实应区分。
- 文档引用的外部灵感（如《苏丹的游戏》、SillyTavern、Pi）用于理解设计，不用于复制其资产、剧情或许可不允许的源码。

## 7. 当前未决定的设计空间

- Agent 引擎是真正 Pi SDK，还是 Worker 上模拟精简工具循环，或别的运行时？
- 世界数据是本机局部存档、云端持久会话，还是混合模型？
- GM 是否具备独立规划/自触发的后台节奏？需要多强一致性？
- “身份关系”如何保存 NPC 的局部知识、误认与揭露链？
- 动态创建规则、物品与成就时，哪些语义可以推断，哪些需要验证和冲突处理？
- 多用户/无账户时怎样保持状态隔离、迁移与可删除性？
- 未来的故事包采取什么格式？Markdown 技能可能足够；不应先建昂贵规范再寻找问题。

**推进方式：优先造一条能证伪关键假说的最小体验，不要先替未来规定最终答案。**

# GM Harness 的器官与 DNA · 可执行最小实验

> 2026-10-16 原型。**器官**是可替换的具体功能代码实体；**DNA**是最小可复现的输入→处理→输出样本，而不是「永远应该长这样」的约束。
>
> 设计理由：开发前先发现哪些功能真正必要，留下能够复制、组合、变异、验证的最低证据。未来 Agent 可以合并器官、换语言、换存储、换模型、重新定义结构。

## 快速复现

在仓库根目录：

```sh
node experiments/gm-organs/dna.mjs
```

不需要 `npm install`、云端 API Key、Cloudflare、数据库或图片。程序通过 Node.js 的断言演示两轮 GM 行为。真实实现源于 [organs.mjs](organs.mjs)，最小“性状”与反例在 [dna.mjs](dna.mjs)。

**验证范围**：纯内存 + 模拟模型的函数示例；不是“Pi SDK 已运行”“DeepSeek 已联网”“在线存档已安全”或“AI 自由剧情已完成”。

## GM 的最小启动层（新增）

- [SYSTEM.txt](SYSTEM.txt)：**一句话**的 GM / DM 启动提示词；无需在这里遍历剧情。
- [GM.md](GM.md)：主持经验的**可选附录**。关于自由行动、因果连续、角色局部认知、惊奇和工具职责的观察，而非必须执行的故事清单。
- [dna.mjs](dna.mjs)：现在会实际读取 `SYSTEM.txt`、验证传入 GM 器官，并模拟按需查阅 `GM.md`，不向真实模型发请求。
- [organs.mjs](organs.mjs)：`makeGM({model, library, world, approve, systemPrompt})` 可接收外部提示。文件格式、器官参数均是实验协议，可被替代。

**注意：**现有实际云端 `/api/story/turn` 路由还没有接入这套 GM 提示词；此处是独立运行 DNA 验证，并非宣称公网 AI 主持已升级。

## 六种候选器官及其最小 DNA

| 功能器官（当前命名） | 最小输入 | 可观察输出/行为 | 演化空间 |
| --- | --- | --- | --- |
| **读书者** `makeLibrarian` | 总纲、`辽东/low` 一小段设定、附录索引 | 需要时返回指定分卷/附录；没有命中的书返回 null | RAG、文件检索、远端丛书索引 |
| **世界账本** `makeWorld` | 一份初始状态、带修订号的 JSON 变更 | 提交后状态更新、版本+1、变更留痕；冲突和越权拒绝 | DB、事件溯源、并发事务、校验规则 |
| **身份透镜** `perceiveIdentity` | 地区、观察者、真实/展示身份、NPC 信念 | 守门人称“可疑来客”，议事官称“上使大人” | 不同 NPC 的知识图与多重伪装 |
| **UI 表达器** `describeView` | 故事文字、状态、几张卡 | 返回纯数据 `text/table/cards`，不执行任意 HTML | 聊天气泡、可交互表格、实时图表 |
| **素材索引** `chooseAsset` | `["辽东","边镇"]` 标签 | 按需找到 `art.frontier` 的素材 ID 与路径 | CDN、分辨率选择、按需 WebP/GIF |
| **GM 驱动壳** `makeGM` | 玩家自由发言、当前世界、书卷、可替换模型 | 模型提议故事变更 → 调用方批准 → 世界提交 → 返回 UI | Pi、其他 Agent SDK、Worker Tool Loop |

这六种并不意味着最终一定要有六个器官。例如“读书者”与“素材索引”可以是同一种检索工具，“身份透镜”可以成为世界查询工具，UI 可以交给现成组件库。

## 最小可观察故事（整套 DNA 的结合）

```text
初始：玩家真实身份是“京师流亡小吏”，自称“权臣密使”
世界：身在辽东低层，守门人认为他是外来奸细
输入：我救下纸扎匠，接受他的纸人侍者
模型样本：叙述遇见纸人；提议将纸人写进 cards，并记下事件
Harness：验证变更，版本从 0 → 1
输出：一段对话 + 身份状态表 + 一张“纸人侍者”卡
输入：让先前的纸人帮我送信
模型样本：第二轮从状态看到已有纸人，能自然继续故事
验证：版本未被无修改的对话虚增；不同 NPC 仍有各自称谓
```

需要注意：本示例中“模型”是**可预测的模拟函数**，只是验证器官之间的信息通路；真正的自由世界编写能力必须接入模型后再测。

## DNA 不是对未来的专制

建议未来 Agent 为每个新器官保留以下最小资料：

```text
器官：它解决什么需求？
DNA：什么最短输入，能产生什么可复现行为？
失效示例：什么输入会失败，为什么？
客观边界：哪些事情由运行环境决定？
可替换性：更简单、更强或更通用的实现能否取代它？
```

先保存**可复制的发现**，后寻找更优秀的实现；不要为了“凑齐六个器官”“满足示例格式”“限制创作自由”发明不存在的需求。

## 与现实产品的距离

- 目前账本数据只存在当前 JS 进程的内存里；游客多会话、数据库持久化、原子冲突、跨设备恢复**尚未实现**。
- `approve` 在样本中是最小示范授权；真实部署需要服务端会话所有权、输入校验、资源与成本限制、隐私及审计。
- `makeGM` 只是接可替换的模型函数，没有真正的工具循环、动态地图自动发现或长期规划。
- `chooseAsset` 返回资源 ID 与候选路径，但不会加载、缓存或把图片推送到游客前端。
- 没有变更现有三个网站与 Cloudflare Worker 的上线行为。
- 世界书和人格身份仅是示例数据；没有固定地区、层级、词汇、物品或故事数量要求。

若继续研究：先把其中**一种真实、任意的游客行动**送给真实模型，让它自主提出一个新世界实体，再通过服务端独立批准、保存，在下一轮可靠读回。实际失败与成功都应该记入接手日志，而不是为了满足设计去伪造通过。
